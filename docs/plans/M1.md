## Goal

The whole sensing and bookkeeping path works end to end in simulation, through the real protocols:
a simulated phone discovers and pairs with the server, sends UDP marker frames and answers clock
sync; the server calibrates the camera from floor tags, tracks tags and cars in floor millimetres with
measured pose ages; the admin assigns tag roles and builds the road network on the dashboard; roles
and the measured layout persist across restarts.

## Out of scope (do not build)

Car links to the server, manual drive, motion control, planning, reservations, missions, Groq, login
(M8), the Android app (M2), firmware (M3), lens profiles and the calibration/venue *wizard* (M4; M1 has
the building blocks: suggest, measure, presets). Do not add later-milestone sections to config.

### Step 6 — Localization and the world model

**Files:** `server/src/duoware/localization/{__init__,geometry,calibration,floor_tags,world}.py`.
Tests: `test_geometry.py`, `test_calibration.py`, `test_world.py`.

- `geometry.py`: `heading_from_corners`, `square_corners(cx, cy, size, yaw)` (port), `wrap_deg`,
  `to_floor(H, pts)`, `side_length_mm(corners)`, `parallax_correct(pts, nadir, scale)` =
  `nadir + (pts − nadir) / scale`, `apply_offset(center, heading, offset_mm)` (forward/left in the car frame;
  +left is 90° counter-clockwise from heading, i.e. heading − 90° in this clockwise frame).
- `floor_tags.py`: `FloorTags(registry)` holds the floor tags' positions: origin fixed at `(0, 0, −90)`;
  typed-in poses; auto-located positions (DUO-WARE 1 `place_anchor`, `place_frames`, `place_move_tol_mm`,
  size warning). `unplace(id, reason)`. Rebuilt when the registry's floor tags change (registry observer):
  any change to a floor tag's role/size/origin/pose clears auto-located positions and bumps a `version`.
- `calibration.py`: `CameraCalibration(cam, floor_tags, tuning.localization)` ported from DUO-WARE 1
  `CameraCalibration` with these changes: uses `FloorTags` instead of `WorldConfig`; no RESTORED state
  (no saved fits in M1); **outlier handling per D28**: after a homography fit, a non-origin auto-located
  tag whose corners are RANSAC outliers is `unplace`d (event `camera`, key `floor_tag_moved`) and the fit is
  kept; during the locked-fit check, compute the residual per visible placed tag: if exactly one
  non-origin auto-located tag exceeds the tolerance and the rest are within it, unplace that tag (camera
  stays `OK`); if more than half exceed it → `MISALIGNED` (and refit after `drift_frames`). Calibration
  status changes are `camera` events.
  `nadir()` = image centre through `H`. `footprint()` polygon.
- `world.py`: `WorldModel(settings, registry, floor_tags, clock, events)` implements `FrameSink`:
  - `on_frame(session, frame, recv_ns)`: skip poses if the session's `ClockSync` is not ok (tags still
    marked seen, positions null); per marker compute server capture time (`marker_capture_ns` → `to_server_ns`);
    feed floor-tag markers (registry roles `node`/`anchor`) to the camera's calibration; if the camera is usable
    (`OK`/`WEAK`), map every other marker to the floor. Record the frame's age in `CameraStats`.
  - Car tags: floor corners → measured side → parallax scale `s = side / size_mm` (reject frames with
    `s > parallax_max_scale` or `s < 1/parallax_max_scale`; EMA with `parallax_ema`, per car, initialised to the
    first accepted value); centre corrected towards the nadir by `s`; heading from corners (unchanged by the
    scaling) + `heading_offset_deg`; rotation centre via `offset_mm`. Store `CarPose(x, y, heading, capture_ns, cam)`.
  - Multiple cameras seeing one tag (not in M1 sims, but keep the structure): use the freshest observation from a usable camera.
  - `snapshot(now_ns) -> WorldSnapshot`: per tag `TagObs(id, seen, cams, x, y, heading, capture_ns, size_mm, size_warn)`
    (last known kept for registered tags), per car pose with `age_ms` and `fresh`, per camera calibration info.
  - Unregistered and `ignore` tags are reported but never used for anything else.

**Tests:** geometry helpers; calibration model selection 1/2/≥3 tags (similarity/affine/homography) with a
synthetic pinhole camera (use `duoware.sim.camera_model` once step 9 exists — until then a small local helper

### Step 7 — Road-network layout

**Files:** `server/src/duoware/layout/{__init__,graph,suggest,service}.py`.
Tests: `test_layout_graph.py`, `test_layout_suggest.py`, `test_layout_service.py`.

- `graph.py` (pure): `build_edges(nodes: Mapping[int, tuple[int, int]]) -> list[tuple[int, int]]` — pairs
  `(r, c)`–`(r, c+1)` and `(r, c)`–`(r+1, c)` only, `a` = smaller `(row, col)`; `fit_grid_rotation(nodes_grid,
  positions, edges) -> float` (D27); `edge_geometry(a, b, positions, rotation, is_row_edge) -> (length, bearing, angle_error)`;
  `validate(layout, rules, cars, footprints) -> list[Warning]` implementing every warning code of §7.5.
- `suggest.py` (pure): `suggest_grid(positions: Mapping[int, (x, y)], gap_fraction) -> Suggestion(rotation_deg,
  spacing_mm, grid: dict[id, (r, c)], conflicts)`. Algorithm: nearest-neighbour vector per tag → angle folded
  with the 4θ circular mean → rotate all positions by −θ → sort each axis; start a new column/row when the gap
  exceeds `gap_fraction ×` median nearest-neighbour distance → indices from 0. Same `(r, c)` twice → conflict,
  no suggestion for those tags. `spacing_mm` = median nearest-neighbour distance.
- `service.py`: `LayoutService(db, registry, world, settings, safety, events, clock)`:
  - Stored doc: `{"version", "measured_wall_ms", "grid_rotation_deg", "positions": {id: [x, y]}, "blocked_nodes": [ids], "blocked_edges": [[a, b]]}`.
  - `current(now_ns) -> Layout` (PROTOCOL.md §7.5 shape): combines registry nodes, stored positions, admin
    blocks, `map.toml [blocked]`, obstacle tags (live positions; `radius_mm` or the default; a node is blocked when
    its position is within the radius, an edge when the segment passes within it), moved nodes, outside-view
    nodes (not inside any calibrated camera footprint), edge states, warnings.
  - `measure(expected_version, operator)`: safety rule; every node with a `grid` must be currently seen by a
    usable camera (`nodes_not_visible`); positions are the world model's current floor positions of those tags;
    stores, bumps `layout_version`, logs a `layout` event with positions and warnings as facts.
  - `set_blocked(nodes, edges, expected_version, operator)`; validation: IDs must be nodes, edges must be in
    `build_edges`.
  - `tick(now_ns)` (called by the state broadcaster each snapshot): node-moved detection
    (`node_move_tol_mm` for `node_move_confirm_s`, cleared when back within tolerance or re-measured), logging
    `layout` events on state changes only.
  - Registry observer: a node's `grid` change removes it from `positions` (it becomes `unmeasured`);
    bumps `layout_version`.
  - `export()` / `import_(doc)` for venue presets; `check_against_live()` for preset apply (matched/moved/missing).

**Tests (A5, A6):** property test (A5) with `random.Random(seed)` loops (no extra dependency): no edge between
nodes differing in both row and column, none spanning more than 1, none across a missing node; grid rotation on
the sim layout 8 ± 0.5°; each warning code; suggestion on the sim positions and the A6 random layouts; obstacle

### Step 9 — Simulator

**Files:** `server/src/duoware/sim/{__init__,__main__,scenario,camera_model,detector_model,world,car_physics,car_server,script,phone}.py`.
Tests: `test_sim_camera.py`, `test_sim_detector.py`, `test_sim_car.py`, `test_sim_phone.py`.

- `scenario.py`: frozen dataclasses for `config/sim.toml` (same strictness as `settings.py`); `load_scenario(path)`.
- `camera_model.py`: `PinholeCamera(position_mm, tilt_deg (pitch, roll), yaw_deg, resolution, hfov_deg, k1)`:
  `project(points_xyz_mm) -> (px, visible)` with radial distortion `k1` (same model as DUO-WARE 1
  `radial_lens_maps`: focal length from `hfov`, centre at image centre); floor points have z = 0, car tags z =
  `tag_height_mm`. Tag corners in 3D from `square_corners` and yaw. Camera looks straight down (−z), image +x ≈
  floor +x rotated by `yaw_deg`, then tilted by pitch/roll.
- `detector_model.py`: `DetectorModel(phone_model, rng)`: `observe(tags_px, velocities_px_s, exposure_ns) ->
  list[Marker]`: blur length = image speed × exposure; detection probability piecewise-linear through
  (`blur_ok_px`, 1), (`blur_half_px`, 0.5), (`blur_zero_px`, 0); Gaussian corner noise `corner_noise_px`; a tag
  with any corner outside the image is not detected; timing draws for `pipeline_ms` and `detect_ms`.
- `car_physics.py`: `CarPhysics(car_cfg)`: state `(x, y, heading, v_left, v_right)`; `command(l, r, ttl_ms, now_ns)`;
  `step(dt_s, now_ns)`: target wheel speed = 0 if |pwm| < `dead_zone_pwm` else `sign × max_speed × (|pwm| −
  dead) / (255 − dead)`, right wheel × `right_gain`; first-order approach with `time_constant_ms` (spin-up and
  coast); TTL expiry → brake (target 0 with a time constant of `time_constant_ms / 3` for 150 ms, then coast);
  differential-drive kinematics about the axle midpoint with `wheel_base_mm`. Emits `X` on expiry.
- `car_server.py`: one asyncio TCP server per car on `tcp_port`: line framing exactly per §5 (31-char limit,
  `\r` ignored, `E long` + stop), uses `protocol/car.py`, applies `link_delay_ms` before a command takes effect,
  replies per §5.2/§5.3 (`ID <name> 0.1.0-sim 1 ttl,led <uptime_s>`), sends `BOOT <name> 0.1.0-sim power` on each
  new connection. The server does not connect to it in M1; the tests do.
- `script.py`: `ScriptDriver` (M1 only, `[script] enabled`): per car, follows its route of tag IDs by issuing
  `CarPhysics.command` directly (bypasses TCP): turn in place towards the next tag at `turn_deg_s`, then drive at
  `speed_mm_s`, stop within 5 mm (uses the sim's **true** pose — it is the simulated world, not the server's
  controller), repeat. Commands are refreshed like a real controller (TTL 300, every 100 ms).
- `world.py`: `SimWorld(scenario, clock)`: steps physics at 200 Hz; keeps a pose history per car (for blur
  sampling and ground truth at a capture instant: `true_pose(car, t_ns)`); floor tags hidden when their centre is
  inside a car's footprint rectangle (`cars.toml footprint_mm`, centred on the rotation centre).
- `phone.py`: `SimPhone(scenario, world, clock)`: phone clock = `mono_ns × (1 + drift_ppm·1e-6) + offset`;
  discovery: listen on the beacon port for `[server] discovery_wait_s` when `[server] discovery` is true,
  else / as fallback use `[server] host`, `http_port`, `frames_port` from the scenario; WebSocket `hello` with the pair code (scenario or `DUO_PAIR_CODE`), store the token in
  memory; per frame at `fps`: capture instant `t_cap`, project tags at their poses sampled over the exposure
  (true poses at `t_cap … t_cap + exposure`), detector model, then schedule the UDP send at
  `t_cap + pipeline + detect + network delay` (drop per `drop_fraction` and burst model); answer `sync` from the
  frames socket immediately with its clock; send `status` at 1 Hz; apply `settings` (exposure changes the blur).
  Expose `truth_log` (seq → capture instant, true car poses, true send/arrival instants) for tests.
- `__main__.py`: `python -m duoware.sim [--scenario PATH]` runs world + script + phone + car servers until Ctrl-C.

**Tests:** projection of a known point; distortion moves corners outward/inward as expected by sign; detector
probability curve and exposure effect (3 ms vs 26 ms at 300 px/s); car physics: below dead zone no motion,
asymmetry curves the path to the expected side, TTL expiry stops within 150 ms + coast, spin in place keeps the
axle midpoint fixed; car server: every §5 rule over a real TCP connection (`?`, `P`, `S` → `OK S`, `M` then
silence → `X 1`, 32-char line → `E long`, `M 300 0 10` → `E range`); sim phone pairs with a real server app
and its frames are accepted (can be part of step 10).
