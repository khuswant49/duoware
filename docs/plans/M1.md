## Goal

The whole sensing and bookkeeping path works end to end in simulation, through the real protocols:
a simulated phone discovers and pairs with the server, sends UDP marker frames and answers clock
sync; the server calibrates the camera from floor tags, tracks tags and cars in floor millimetres with
measured pose ages; the admin assigns tag roles and builds the road network on the dashboard; roles
and the measured layout persist across restarts.

## Out of scope (do not build)

Car links to the server, manual drive, motion control, planning, reservations, missions, Groq, login
(M8), the Android app (M2), firmware (M3), lens profiles and the calibration/venue *wizard* (M4; M1 has
the building blocks: suggest, measure, presets), the TCP frames listener and `adb reverse` (M2; M1 only
writes the pure TCP framing codec), storing benchmark results (M2). Do not add later-milestone sections to config.

### Step 6 — Localization and the world model

**Files:** `server/src/duoware/localization/{__init__,geometry,calibration,floor_tags,world}.py`.
Tests: `test_geometry.py`, `test_calibration.py`, `test_world.py`.

- `geometry.py`: `heading_from_corners`, `square_corners(cx, cy, size, yaw)` (port), `wrap_deg`,
  `to_floor(H, pts)`, `side_length_mm(corners)`, `parallax_correct(pts, nadir, scale)` =
  `nadir + (pts − nadir) / scale`, `apply_offset(center, heading, offset_mm)` (forward/left in the car frame;
  +left is 90° counter-clockwise from heading, i.e. heading − 90° in this clockwise frame).
- `floor_tags.py`: `FloorTags(registry)` holds the floor tags' positions: origin fixed at `(0, 0, −90)`;
  typed-in poses; auto-located positions (DUO-WARE 1 `place_anchor`, `place_frames`, `place_move_tol_mm`,
  size warning). `unplace(id, reason)`. Rebuilt when the registry's floor tags change (registry observer):
  any change to a floor tag's role/size/origin/pose clears auto-located positions and bumps a `version`.
- `calibration.py`: `CameraCalibration(cam, floor_tags, tuning.localization)` ported from DUO-WARE 1
  `CameraCalibration` with these changes: uses `FloorTags` instead of `WorldConfig`; no RESTORED state
  (no saved fits in M1); **outlier handling per D28**: after a homography fit, a non-origin auto-located
  tag whose corners are RANSAC outliers is `unplace`d (event `camera`, key `floor_tag_moved`) and the fit is
  kept; during the locked-fit check, compute the residual per visible placed tag: if exactly one
  non-origin auto-located tag exceeds the tolerance and the rest are within it, unplace that tag (camera
  stays `OK`); if more than half exceed it → `MISALIGNED` (and refit after `drift_frames`). Calibration
  status changes are `camera` events.
  `nadir()` = image centre through `H`. `footprint()` polygon.
- `world.py`: `WorldModel(settings, registry, floor_tags, clock, events)` implements `FrameSink`:
  - `on_frame(session, frame, recv_ns)`: skip poses if the session's `ClockSync` is not ok (tags still
    marked seen, positions null). **Scan semantics (PROTOCOL.md §2, D32):** only `full` frames go to the
    camera's calibration, auto-location and (via the snapshot) node-moved detection; in a `roi` frame a tag
    counts as not seen only if its ID is in `searched`. **Camera mode (D36):** while the session's latest
    `status.app_mode` ≠ `tracking`, poses are recorded but flagged `usable_for_control = false`.
    **Resolution change (D34):** when `w`/`h` differ from the fit's resolution with the same aspect ratio,
    scale `H` by the pixel ratio and mark the camera `MISALIGNED` until the next full frame's floor-tag
    residual check passes; a different aspect ratio drops the fit; per marker compute server capture time (`marker_capture_ns` → `to_server_ns`);
    feed floor-tag markers (registry roles `node`/`anchor`) to the camera's calibration; if the camera is usable
    (`OK`/`WEAK`), map every other marker to the floor. Record the frame's age in `CameraStats`.
  - Car tags: floor corners → measured side → parallax scale `s = side / size_mm` (reject frames with
    `s > parallax_max_scale` or `s < 1/parallax_max_scale`; EMA with `parallax_ema`, per car, initialised to the

### Step 9 — Simulator

**Files:** `server/src/duoware/sim/{__init__,__main__,scenario,camera_model,detector_model,world,car_physics,car_server,script,phone}.py`.

- `scenario.py`: frozen dataclasses for `config/sim.toml` (same strictness as `settings.py`); `load_scenario(path)`.
- `camera_model.py`: `PinholeCamera(position_mm, tilt_deg (pitch, roll), yaw_deg, resolution, hfov_deg, k1)`:
  `project(points_xyz_mm) -> (px, visible)` with radial distortion `k1` (same model as DUO-WARE 1
  `radial_lens_maps`: focal length from `hfov`, centre at image centre); floor points have z = 0, car tags z =
  `tag_height_mm`. Tag corners in 3D from `square_corners` and yaw. Camera looks straight down (−z), image +x ≈
  floor +x rotated by `yaw_deg`, then tilted by pitch/roll.
- `detector_model.py`: `DetectorModel(phone_model, rng)`: `observe(tags_px, velocities_px_s, exposure_ns) ->
  list[Marker]`: blur length = image speed × exposure; detection probability piecewise-linear through
  (`blur_ok_px`, 1), (`blur_half_px`, 0.5), (`blur_zero_px`, 0); Gaussian corner noise `corner_noise_px`; a tag
  with any corner outside the image is not detected; timing draws for `pipeline_ms` and `detect_ms`.
- `car_physics.py`: `CarPhysics(car_cfg)`: state `(x, y, heading, v_left, v_right)`; `command(l, r, ttl_ms, now_ns)`;
  `step(dt_s, now_ns)`: target wheel speed = 0 if |pwm| < `dead_zone_pwm` else `sign × max_speed × (|pwm| −
  dead) / (255 − dead)`, right wheel × `right_gain`; first-order approach with `time_constant_ms` (spin-up and
  coast); TTL expiry → brake (target 0 with a time constant of `time_constant_ms / 3` for 150 ms, then coast);
  differential-drive kinematics about the axle midpoint with `wheel_base_mm`. Emits `X` on expiry.
- `car_server.py`: one asyncio TCP server per car on `tcp_port`: line framing exactly per §5 (31-char limit,

- `phone.py`: `SimPhone(scenario, world, clock)`: phone clock = `mono_ns × (1 + drift_ppm·1e-6) + offset`;

  else / as fallback use `[server] host`, `http_port`, `frames_port` from the scenario; WebSocket `hello` with the pair code (scenario or `DUO_PAIR_CODE`), store the token in
  memory; per frame at `fps`: capture instant `t_cap`, project tags at their poses sampled over the exposure

  `t_cap + pipeline + detect + network delay` (drop per `drop_fraction` and burst model); answer `sync` from the
  frames socket immediately with its clock; send `status` at 1 Hz; apply `settings` (exposure changes the blur).

  tracked tag was missing; otherwise a `roi` frame listing `track_ids` in `searched` and containing only those

## Proposed changes

_(Sonnet: proposals, with the evidence. Opus decides in the M1 review. I did not touch `PROTOCOL.md` or `DECISIONS.md`.)_

**P1. Record the tag-shape self-calibration (DECISIONS.md, new entry).** The calibration ported from DUO-WARE 1
cannot meet A2(a). With only the origin tag known, unplaced tags are located through a *similarity* fit, then a
homography is fitted to those placed positions, which reproduces their error. In the sim world (phone tilted
2.0°/−1.5°, lens k1 −0.03) that gave node errors of **up to 29.9 mm** (mean about 15 mm; measured with noise 0.07 px,
before any change). I added `localization/refine.py`: a small Levenberg-Marquardt fit (numpy only) of the 8 homography
parameters and the pose of every automatically located tag, so that each tag's image is a square of its printed
size, with the origin (and typed-in tags) held fixed. Result: **max node error 1.9 mm** in `test_calibration.py`
(9 tags, noise 0.07 px) and **2.1-2.2 mm** in the end-to-end run. It runs at every successful homography fit and
needs no hand measurement (D13). Suggested wording for D28: "after a homography fit, the positions of automatically
located tags are refined together with the mapping from the known tag shape".

**P2. `size_mm` is used twice in PROTOCOL.md §7.4.** "`GET /api/tags` returns the document plus the live fields of
`state.tags`", but `size_mm` is the *printed* size in the document and the *measured* size in `state.tags`. I return
`size_mm` = printed and add `measured_size_mm` = measured (`TagEntry`, `dashboard/src/api/types.ts`). Please write
that into §7.4.

**P3. Additive fields the server sends that §6.2 / §7 do not show** (additive, so no version change):
`cameras[].rx_version` and `cameras[].rx_bad_marker` (§2 requires counting both and showing "protocol mismatch"),
`cameras[].clock` (the phone's sync clock), `cars[].pose.usable_for_control` (false in `setup`/`benchmark` mode or
without sync/calibration; the M1 stand-in for `stopped_reason` `camera_mode`), `caps` on `GET /api/cameras` (as
specified in §7.2).

**P4. Error codes and shapes missing from §7.** `preset_exists` (409, saving over an existing preset without
`overwrite`), `not_found` (404: unknown preset, camera without calibration), `confirm_required` (listed), and
`version_conflict` also for `POST /api/layout/measure`, `PUT /api/layout/blocked` and preset apply (details
`current_layout_version` / `current_registry_version`). `validation` is also used for malformed request bodies, bad
query values (`limit`) and path parameters that are not integers.

**P5. `blocked_by` values (§7.5).** Besides `admin`, `config` and `tag:<id>`, an edge touching a `moved` node has
`blocked_by` `"moved:<node id>"` (the node itself has state `moved` and `blocked_by` null).

**P6. Clock-sync slope (§3.3).** A least-squares line over the best-RTT samples is worse than a constant while the
chosen samples span only a few seconds: with the simulated 0-3 ms one-way jitter and 20 samples (2 s) the line fit
had mean error 0.37 ms, p95 0.9 ms and worst 2.1 ms; the constant had mean 0.17 ms, p95 0.42 ms, worst 0.6 ms. The
plan's "< 0.5 ms after 20 samples" needs the constant. `ClockSync` therefore uses the slope only when the chosen
samples span at least 25 % of `window_s` (`SLOPE_MIN_WINDOW_FRACTION` in `ingest/clocksync.py`; a named constant, not
in `tuning.toml`, because it is an estimator property). Suggest adding this sentence to §3.3 and, if Opus prefers, a
`clock_sync.slope_min_window_fraction` key.

**P7. Calibration must fit from whichever tags are steady (D28).** DUO-WARE 1 restarts the 10-frame averaging
whenever the set of visible placed tags changes, and restarts a tag's 15-frame location count whenever the tag is
hidden for one frame. With two cars driving over the nodes neither ever completed (the camera took 19 s to reach `OK`
and then only with 7 of 9 tags placed). `CameraCalibration` now keeps a steady-frame buffer per tag (cleared only when
that tag's corners move) and fits from the visible tags that have a full buffer; a hidden tag keeps its location
progress. `OK` now comes 8.7 s after applying the preset (3 full scans per second, so this is bounded by
`settle_frames` and `place_frames` in `tuning.toml`).

**P8. A step-10 ordering slip.** The plan says to wait for the camera to be `OK` and synced *before* applying
`sim_3x3`, but without floor-tag roles the camera cannot calibrate. The end-to-end test waits for *synced*, applies the
preset, then waits for `OK`. Likewise the cars are parked between the nodes until the layout is measured (a node
under a car cannot be measured); the scripted driving starts right after `measure`.

**P9. Node-moved detection and measuring use a camera with a good fit only.** Found in the manual check (A9):
applying a preset that changes floor tags resets the fit, and during the `WEAK` phase positions far from the origin
tag are off by about 30 mm, which showed up as a false "node 13 moved" event. `live_position` and `node_position` now
return a position only while the seeing camera is `OK` (regression test
`test_a_recalibrating_camera_never_makes_nodes_look_moved`).

**P10. The nadir is the image centre mapped through the fit, as planned, but that is not the point below the lens.**
With the sim's tilt the two differ by about 78 mm, which costs up to about 3.5 mm of car pose error for an 80 mm-high
tag (A2(d) is met with a large margin: median 3.0 mm). The exact nadir and camera height can be computed from the plane
homography (Zhang-style decomposition, principal point at the image centre); worth doing in M4 with the lens profile.

**P11. Preset `check` right after a preset with different floor tags is mostly "missing".** Applying such a preset
resets the fit (correct, §7.4 "Effects"), so the immediate comparison has no calibrated camera; nodes that were
pushed are found by the normal node-moved detection (2 s) once the camera is `OK` again. With identical floor tags the
fit is kept and `check` is complete (tested). If an immediate answer matters, the apply could keep the old fit until
the new floor tags are located.

**P12. Smaller notes.** (a) `GET /api/events` returns the newest `limit` events with `id > since_id`, newest first.
(b) The Origin check applies only when an `Origin` header is present (curl and the TestClient send none). (c) Plan
step 1 lists the `Tuning` tables without `link`, `phone` and `phone.thermal`; they exist in `tuning.toml`, so they are
loaded too. (d) WebSocket pings (5 s / 10 s, §4.3) are set on uvicorn in `__main__.py` and in the test harness, not in
the app object. (e) The simulator's `SimPhone.switch_session` got a `gap_s` parameter: A12 needs the phone to stay off
the air for longer than `stale_ms + 100 ms`, which a reconnect within a few milliseconds never does.

### Known gaps

- **Simulation only.** No hardware, no Android build, no firmware. The phone-facing behaviour (timestamps, clock
  sources, thermal, real detection and blur) is modelled, not measured; the sim reports CPU and thermal as `null`.
- **No component tests of the React pages**: the dashboard tests cover the pure logic (transform, client, backoff,
  message parsing, types against the §6.2 example). The pages were checked by hand (A9). At about 800 px width the Live
  page scrolls horizontally, and the map is drawn small because the camera footprint sets the bounds.
- The TCP frames listener, `adb reverse`, `GET /api/beacon`, the preview endpoint and benchmark storage are M2 (only
  the TCP framing codec exists). `/ws/phone` accepts and ignores `bench` and keeps only the latest preview in memory.
- Car links do not exist yet: `cars[].link.state` is always `disconnected` and `stopped_reason` is `estop` or `no_link`.
- Node-moved detection compares single-frame positions; `measure` stores the averaged, refined positions. The nadir

- `ingest/beacon.py` assumes a /24 subnet for the directed broadcast and is untested on a real tether or hotspot.
- The end-to-end test relies on a 1 ms Windows timer (`sim/timing.py`) for a smooth 30 fps; it passed three of three
  consecutive runs here but has not been run elsewhere.
