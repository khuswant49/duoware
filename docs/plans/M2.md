## Goal

The phone is a fast, steady marker sensor: the highest frame rate its camera sustains at a short exposure,
detection in C++ with ROI tracking, frames over UDP (USB tether, Wi-Fi or phone hotspot) or TCP (`adb
reverse`), found without typing an IP, measured end to end, and held for hours without Android throttling it
unpredictably. The server gains the TCP transport, `adb reverse`, `/api/beacon`, previews, benchmark storage,
frame recordings with a blur report, and the M1 review fixes.

## Out of scope (do not build)

Car links, firmware, manual drive (M3); lens correction and the venue wizard (M4); any change to how the server
localizes (beyond F1–F14); a Play-store build; iOS. No later-milestone config sections.

## App architecture

```
MainActivity (Views)   mode WIRED/WIRELESS, camera choice, Start/Stop, Setup/Tracking, Benchmark, pair code,
   │ binds             manual host, live stats, dim "demo" screen, sustained-performance window flag
SensorService (foreground, type camera; owns everything below; partial wake lock)
   ├─ CameraController    Camera2: one YUV ImageReader, manual exposure/ISO/frame duration, AF/AWB once then
   │                      locked, D41 processing off, capabilities for hello, CaptureMeta ring (exposure, skew)
   ├─ FramePipeline       pipeline thread: Image mailbox → one JNI call → result buffer → FrameWriter → sender
   │    └─ native (C++)   Pipeline, RoiTracker, Detector (cv::aruco on Mat views), preview downscale
   ├─ FrameSender         sender thread, depth-1 slot, UDP DatagramChannel or TCP SocketChannel (§2.1)
   ├─ SyncResponder       answers §3 sync on the frames socket, stamps t2/t3 on the sync clock
   ├─ Discovery           §4.1/§4.2 per mode: beacon listener, adb probe, Wi-Fi gateway probe, manual host
   ├─ NetworkBinder       binds sockets to the chosen Network / interface address / loopback
   ├─ Session             OkHttp WebSocket: hello/welcome/settings/status/bench/preview, token storage
   ├─ ClockSource         §3.1 sync-clock decision; now() on that clock
   ├─ PerfManager         sustained mode, ADPF hint session, CPU load, core frequencies, wake/Wi-Fi/multicast locks
   ├─ ThermalGovernor     pure ladder logic (§4.4) + an Android adapter feeding it once a second
   ├─ PreviewEncoder      preview thread: downscaled Y → JPEG (OpenCV imencode) → DWP1 binary message
   ├─ Stats               stage timings in fixed rings; percentiles without allocation
   └─ Benchmark           the §4.7 matrix, results table, `bench` message
```

### Threads and the hot path

| Thread | Does | Must never |
| --- | --- | --- |
| `cam` (HandlerThread) | Camera2 callbacks; `ImageReader` listener: `acquireLatestImage()`, stamp `avail_ns`, put it in the one-slot mailbox (closing an unprocessed older image there and counting it skipped); `onCaptureCompleted` → `CaptureMeta` ring | detect, allocate per frame in our code, touch the network |
| `pipeline` | take the mailbox image; JNI `nativeProcess`; close the image; `FrameWriter` into a free send buffer; hand it to the sender; stage stats; ADPF `reportActualWorkDuration` | wait on the network or a lock held by another thread for more than a slot swap |
| OpenCV workers | inside `nativeProcess` (parallel windows / full-scan internals) | — |
| `sender` | take the newest ready buffer, stamp `sent_ns` into it, write it (UDP `write`, TCP framed write) | queue old frames (newest wins, `send_dropped`) |
| `sync` | block on the frames socket's read side; answer `sync` immediately | allocate per frame (it runs at ≤ 10 Hz; small allocations here are acceptable) |
| `preview` | encode the latest downscaled Y copy at `preview.fps`, send it | run when the WebSocket send queue is over 64 KB (skip) |
| `ws` (OkHttp) | session messages | — |
| `status` (1 Hz, e.g. a ScheduledExecutor) | CPU, thermal (governor tick), battery, build and send `status` | — |

**Hot-path rules (owner requirement; D31):** in `cam`, `pipeline` and `sender`, our Kotlin code allocates nothing
per frame (preallocated `ByteBuffer`s/arrays, reused `StringBuilder`-free writers, primitive rings). Our C++ code
allocates nothing per frame (buffers and vectors sized at start, `clear()` keeps capacity). OpenCV's
`detectMarkers` allocates internally; that is outside our control and is what the `java_full` vs `native_*`
benchmark measures. No JPEG, logging or JSON library on the hot path.

### Step 3 — Server: one ingest for both transports, the TCP listener, the simulator in TCP mode

**Files:** `ingest/frames.py` (new), `ingest/udp.py` (thin), `ingest/tcp.py` (new), `ingest/sessions.py`,
`api/beacon.py` (moved here from step 4: B2 needs it), `sim/phone.py`, `sim/tcp_link.py`, `sim/scenario.py`,
`config/sim.toml`; tests `test_frames_ingest.py`, `test_tcp.py`, `test_api_beacon.py`, `test_e2e_sim_tcp.py`.

- `FrameIngest(sessions, sink, clock)`: the §2 server rules moved out of `FramesEndpoint` unchanged, as
  `handle(data: bytes, peer_ip: str, reply: Callable[[bytes], None], transport: str, recv_ns: int)`. A frame sets
  `session.reply = reply` (where `sync` requests go) and `session.transport`. The sync loop (per session) calls
  `session.reply(encode_sync(...))`; UDP's reply is `sendto(frame source)`, TCP's is a framed write on that
  connection.
- `FramesTcpServer`: `asyncio.start_server` on `tcp.frames_port` (0.0.0.0); `TCP_NODELAY` on accepted sockets;
  `TcpDeframer` from M1; every §2.1 rule (B3). One connection per `sid`: a new one closes the old. Registered on
  `sessions.on_closed` to close a session's connection. Bound port in `Services.ports["tcp"]`.
- Simulator: `[phone_model] transport = "udp" | "tcp"` in `sim.toml`/`scenario.py`. In `tcp` mode the sim phone
  discovers with `GET /api/beacon` on 127.0.0.1 (like `wired_adb`), reports `link.mode = "wired_adb"`, opens the TCP
  connection after `welcome`, sends frames with the §2.1 framing (dropping a frame when the previous write has not
  drained, counted as `send_dropped`) and answers `sync` on it.
- `test_e2e_sim_tcp.py`: reuses `tests/harness.py`; pairs, applies `sim_3x3`, waits for `OK`, checks B2 (keep it
  under 25 s; no layout measuring or driving needed).

  capture times. Header line first: `{"t":"recording","v":1,"server_id":…,"started_wall_ms":…,"settings":{…tuning
  [pose], [clock_sync]…}}`.
- `python -m duoware.tools.blur_report FILE --tag ID [--cam N] [--json]`: for every frame where the tag was looked for
  (a `full` frame, or a `roi` frame with the ID in `searched`), whether it was detected, and its image speed at that
  instant: the change of the marker centre between the nearest detections before and after, each within
  `SPEED_WINDOW_MS = 200` (per capture time `cap_ns`), in px/s. Frames without both neighbours are excluded and
  counted. Bins `< 150`, `150–300`, `> 300` px/s (named constants: the DUO-WARE 1 bins, brief §4.1). Prints, per bin,
  frames looked, detected, clean-read ratio; `--json` prints the same as JSON. B8 checks it against the simulator.

### Step 6 — Android: protocol, clock, stats and thermal logic in pure Kotlin (JVM-tested)

**Files (package `com.duoware.sensor`):** `proto/FrameWriter.kt`, `proto/TcpFramer.kt`, `proto/Messages.kt`,
`proto/Beacon.kt`, `clock/ClockSource.kt`, `stats/Percentiles.kt`, `stats/StageStats.kt`,
`perf/ThermalGovernor.kt`, `bench/BenchMatrix.kt`, `net/DiscoveryRules.kt`; tests under `app/src/test/`.

- `FrameWriter(capacity = 8192)`: writes one §2 frame into a caller-owned `ByteArray` with no allocation:
  `begin(cam, sid, seq, capNs, expNs, skewNs, availNs, w, h, full, searched: IntArray, nSearched)`,
  `marker(id, corners: FloatArray, offset)` (corners rounded to 0.1 px by integer arithmetic; `-0.0` written as
  `0.0`), `end(): Int` (length). `sent_ns` is written **last** into a reserved 20-character field

  into `app/src/test/resources/protocol/` with a comment naming the section (the server's A7 test guards the source).
- `ClockSource`: §3.1 as a pure function of (`SENSOR_INFO_TIMESTAMP_SOURCE`, first `cap_ns`, `elapsedRealtimeNanos`,
  `nanoTime`) → `boottime | monotonic | unknown`, plus `now()` on the chosen clock.

  `up_after_s` continuously below `headroom_up` with status < `status_down`. Levels: `fps_steps` first, then

  last valid reading for up to 10 s. Each level has a reason string. Tests: rising headroom, hysteresis, status-only,
  NaN handling, bounds.

- `DiscoveryRules`: pure checks: beacon `v`, `host` inside the interface subnet (address + prefix length),

### Step 7 — Android: native pipeline (C++)

**Files:** `cpp/pipeline.hpp/.cpp`, `cpp/roi_tracker.hpp/.cpp`, `cpp/detector.hpp/.cpp`, `cpp/results.hpp`,
`cpp/preview.cpp`, `cpp/jni_bridge.cpp`, `cpp/test_hooks.cpp` (compiled only when `DUO_TEST_HOOKS` is defined, which
the debug build type sets); `pipeline/NativeBridge.kt`, `pipeline/ResultBuffer.kt`; instrumented tests
`NativeDetectorTest.kt`, `RoiTrackerTest.kt`.

- JNI: `nativeCreate(maxW, maxH): Long`, `nativeConfigure(handle, trackIds: IntArray, fullScanEvery, roiMargin,
  roiMinPx, threads, demoteAfterScans, cornerRefine, aruco3)`, `nativeProcess(handle, y: ByteBuffer, rowStride, w,
  h, capNs, forceFull: Boolean, previewW: Int, result: ByteBuffer, preview: ByteBuffer?): Int`,
  `nativeWorkerTids(handle): IntArray` (called once, not per frame), `nativeEncodeJpeg(src: ByteBuffer, w, h,
  quality, out: ByteBuffer): Int` (preview thread), `nativeDestroy(handle)`. Direct buffers only
  (`GetDirectBufferAddress`); the Y plane is wrapped in a `cv::Mat` header with its row stride, **no copy**.
- `results.hpp`: the result buffer layout, little-endian, with `RESULT_LAYOUT_VERSION = 1`: header (`layout`,
  `n_markers`, `scan` 0 full / 1 roi, `n_searched`, `searched[64]`, `n_windows`, `lost` flag, `detect_ns`), then per
  marker `id` (int32) and 8 float32 corners in full-image pixels. Capacity 64 markers (`MAX_MARKERS`). Kotlin's
  `ResultBuffer` reads it without allocation.
- `Detector`: one `cv::aruco::ArucoDetector` per worker (DICT_4X4_50; `cornerRefinementMethod` from
  `corner_refine`; `useAruco3Detection` from `aruco3` for full scans), preallocated output vectors (`clear()`, never
  shrink), detection in a `cv::Mat` ROI view; corners offset back to full-image coordinates.
- `RoiTracker` (D32, PROTOCOL.md §4.4):
  - A full scan when: the frame index is a multiple of `full_scan_every`, the previous frame lost a tracked tag, no
    tag is tracked yet, or the settings just changed.
  - Tracked set = `track_ids` that have been seen, plus tags promoted because their centre moved more than their own
    side length between two full scans; a promoted tag is demoted after `demote_after_scans` consecutive full scans
    with less movement than that.
  - Prediction: constant velocity from the last two detections to the new `cap_ns` (zero velocity with one detection,
    or when the two are more than `STALE_VELOCITY_MS = 500` apart). Window = the predicted bounding box grown by
    `roi_margin` × side length on every side, at least `roi_min_px` square, clipped to the image.
  - Windows are searched in parallel (`cv::parallel_for_` over windows; the inner OpenCV calls then run serially).
    A tag found in two overlapping windows is reported once (the detection from the window whose centre is nearest
    to the marker's centre). **Duplicate IDs must never leave the phone from overlapping windows** (the server drops
    every entry of a repeated ID, PROTOCOL.md §2).
  - A tracked tag not found in its window → `lost`, the next frame is a full scan, `lost_rescans` +1.
  - Other tags detected inside a window are reported too; `searched` lists only the IDs whose windows were searched.
- Preview: when `previewW > 0`, an area-averaging downscale of the Y plane into `preview` (preallocated, at most
  640 × 480), done before `nativeProcess` returns so the `Image` can be closed.
- Threads: `threads` = 0 → the cores of the fastest cluster (group `/sys/devices/system/cpu/cpu*/cpufreq/
  cpuinfo_max_freq` by value); `cv::setNumThreads`. At start, a warm-up `parallel_for_` records the worker thread
  IDs (`gettid()`) for the ADPF session. No explicit CPU affinity in v1 (Android may deny it; the hint session is the
  supported way to get fast cores).
- **Tests (instrumented, synthetic images made in C++ from `generateImageMarker`, warped into a 1280 × 720 grey
  frame, with optional motion blur by a line kernel):** all 11 markers of a 2-car + 9-floor-tag scene found, corner
  error p95 < 0.3 px with `subpix`; a tag moving 300 px/s at 60 fps stays in its window for 300 frames without a lost
  rescan; a removed tag → next frame full, `lost_rescans` +1; windows at the image edge are clipped (no crash, no
  false detection); two overlapping windows → no duplicate ID; an untracked tag moved between full scans is tracked in
  `roi` frames and demoted after `demote_after_scans` still scans; timings logged (no assert).
- **Phone checkpoint 2** (owner): install the CI build of this step and run the instrumented tests; report pass/fail
  and the logged detection timings.
- **Cloud handoff (end of the cloud session):** a "Handoff after step 7" note under Results: what is done, the CI run
  of the last commit, both checkpoint results as the owner reported them, open problems, and anything the laptop

### Step 9 — Android: discovery, network binding, session, frames and sync transport

**Files:** `net/Discovery.kt`, `net/NetworkBinder.kt`, `net/Session.kt`, `net/FrameSender.kt`,
`net/SyncResponder.kt`, `store/Prefs.kt`.

- Modes (PROTOCOL.md §4.1): **WIRED** — tether interface (`rndis*`, `usb*`, `ncm*` with an IPv4 address, from
  `NetworkInterface`), listen for a beacon 3 s on `0.0.0.0:<beacon_port>` and accept only one whose `host` is in that
  interface's subnet; else probe `http://127.0.0.1:<http_port>/api/beacon` (1 s timeout) → `wired_adb`; repeat every
  5 s. **WIRELESS** — if a Wi-Fi client `Network` exists (`ConnectivityManager`, `TRANSPORT_WIFI`): take a
  `MulticastLock`, listen 3 s, accept beacons from the Wi-Fi subnet; else probe the gateway from `LinkProperties`;
  if the phone is itself the hotspot (`ap*`, `swlan*`, `softap*` interface with IPv4), treat that interface like the
  tether. Repeat every 5 s. **Manual host** (advanced field) is tried last in both modes. Release the multicast lock
  once connected. Show which step is running.
- `NetworkBinder`: Wi-Fi client → `network.bindSocket(channel.socket())` for UDP/TCP and `network.socketFactory` for
  OkHttp; tether/phone hotspot → bind sockets to the interface address (OkHttp through a `SocketFactory` that binds
  before connect); adb → loopback. Nothing uses the default route (mobile data must never carry frames).
- `Session` (OkHttp WebSocket, `pingInterval(5 s)`): `hello` per §4.3 (`device_id`: a UUID created once; `token`
  from `Prefs`; `pair_code` only without a valid token or after `bad_token`; `link` with interface, local IP and for
  Wi-Fi band/RSSI/link speed from `NetworkCapabilities.transportInfo`; `cpu` cores and `cpuinfo_max_freq`; camera
  caps). `welcome`: store a new token, `cam`, `sid`, apply settings, open the frames transport. `error`: show it;
  `bad_token` clears the token and asks for the code; `version` shows "server speaks protocol vN". A closed socket
  (any reason) ends the session: frames transport closed, discovery again after 1 s (a new session, D35). A mode
  switch in the UI does the same in the new mode. `status` every second with every §4.5 field (`null` where not
  measurable). `settings` messages are applied live (camera reconfigured only when resolution, fps, exposure or ISO
  changed).
- `Prefs`: app-private `SharedPreferences` (device ID, token, server ID, mode, camera choice, manual host). The token
  only authorises sending poses on a local network (D6); `EncryptedSharedPreferences` is deprecated and is not used.
- `FrameSender`: UDP — a `DatagramChannel` bound (per `NetworkBinder`) and `connect`ed to `host:frames_port`,
  blocking writes of a direct `ByteBuffer`; TCP — a `SocketChannel` to `127.0.0.1:frames_tcp_port`, `TCP_NODELAY`,
  16 KB send buffer, §2.1 framing, reconnect after 1 s while the session lives. Depth-1 slot with three buffers
  (being filled / ready / being sent): a ready buffer replaced before it was sent counts `send_dropped`.
- `SyncResponder`: the read side of the same channel; on `sync`: stamp `t2` immediately after the read returns, build
  `sync_r`, stamp `t3` just before the write (TCP: after taking the connection's write lock). Its writes go through
  the same channel as frames (NIO serialises concurrent writers).
- Wireless: `WifiLock(WIFI_MODE_FULL_LOW_LATENCY)` held while tracking in `wireless`.
